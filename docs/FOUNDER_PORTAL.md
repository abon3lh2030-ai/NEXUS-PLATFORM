# NEXUS Founder Portal

نظام داخلي خاص بمؤسس NEXUS داخل نفس الموقع، على `/founder`. حساب المؤسس منفصل عن حسابات الشركات، ولا يوجد تسجيل عام له.

## الدخول

- **الرابط:** `<PUBLIC_APP_URL>/founder/login`. محليًا هو `http://localhost:5173/founder/login`، ويعمل مع `npm run dev` وليس `npm run demo`.
- **الخطوات:**
  1. البريد وكلمة المرور.
  2. رمز التحقق بخطوتين (TOTP)، ويُطلب في كل دخول. في أول دخول يظهر QR تمسحه بتطبيق مصادقة.
  3. في أول دخول فقط يجب استبدال كلمة المرور الأولية. تغيير كلمة المرور ينهي الجلسات، فتدخل من جديد بالكلمة الجديدة.
- **نسيت كلمة المرور:** «نسيت كلمة المرور» في صفحة الدخول ترسل رابطًا للبريد عبر Supabase Auth. يجب ضبط Site URL وRedirect URLs في Supabase على رابط الموقع المنشور.

## الحماية

كل هذه الضمانات تُفرض على الخادم وقاعدة البيانات، لا على الواجهة فقط:

- **فحص كل طلب:** كل طلب إلى `/founder/*` يُتحقق منه مع Supabase Auth في كل مرة بدون كاش، ثم يُطلب:
  - صف في `founder_accounts`،
  - و`aal2` (التحقق بخطوتين)،
  - وأن كلمة المرور الأولية قد تغيّرت.
- **غير المؤسس** يحصل على 404، فلا يُكشف وجود البوابة.
- **جداول `founder_*`:**
  - RLS مفعّل وإجباري، وكل الصلاحيات مسحوبة من `anon` و`authenticated`.
  - لا يصل لها المتصفح حتى بتوكن المؤسس نفسه.
  - الطريق الوحيد إليها هو الـ API، بـ service role ومن خلف حارس المؤسس.
- **المدخلات:** كل حقل محدد في whitelist بـ Zod (`apps/api/src/services/founder/collections.ts`)، وأي حقل غير معروف يُرفض.
- **المستندات:** في bucket خاص اسمه `founder-documents` بدون أي سياسات، ويُوصل لها بروابط موقّعة مؤقتة فقط.
- **سجل العمليات `founder_audit_log`:**
  - يسجّل كل دخول وكل إنشاء أو تعديل أو حذف (قبل/بعد) وكل تصدير.
  - لا يمكن تعديله أو حذفه، إلا أن حذف المستخدم يفرّغ `user_id` فقط.

## إدارة الحساب (من الخادم فقط)

```bash
node --env-file=.env scripts/founder-account.mjs create <email> --out <file> [--admin]   # إنشاء (كلمة المرور تُكتب في الملف فقط، mode 600)
node --env-file=.env scripts/founder-account.mjs reset-password <email> --out <file>     # كلمة مرور مؤقتة جديدة
node --env-file=.env scripts/founder-account.mjs reset-mfa <email>                       # عند فقدان جوال المصادقة
```

## الترابط التلقائي

- **صفقة تصبح «ناجحة»:**
  - يُسجَّل إيراد تلقائي (مصدره `deal_won`).
  - يزيد عدد العملاء، وتتقدم أهداف «الشركات المتعاقدة».
  - إرجاع الصفقة من «ناجحة» يحذف هذا الإيراد.
- **شراء جهاز** (من خطة الاستقلال التقني ← الأجهزة):
  - يُسجَّل مصروف على بند الميزانية وعلى المرحلة، ويزيد عدد ما تم شراؤه.
  - حذف هذا المصروف يرجع العدد كما كان.
- **مصروف على بند ميزانية** يُحسب على مرحلته تلقائيًا.
- **إكمال مهمة استقلال تقني** يتطلب إثباتًا أو ملاحظة، ويحدّث نسب الإنجاز ولوحة «أين وصلنا الآن؟».
- **نسبة الاستقلال التقني** = وزن القدرات التي تعمل اليوم على بنية تملكها NEXUS ÷ وزن كل القدرات.

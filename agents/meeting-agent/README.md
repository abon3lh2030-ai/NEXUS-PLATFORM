# NEXUS meeting agent

A LiveKit Agents worker. It joins NEXUS meeting rooms when dispatched by the API.

**What it does in a meeting:**
- **Announces itself:** posts a chat message saying it is an AI employee and that the meeting is transcribed (and recorded, if the company records audio).
- **Transcribes:** every speaker is transcribed. Silero VAD cuts speech into sentences, and each sentence goes to the `STTProvider`. The lines are sent to NEXUS, which names each speaker from their NEXUS account.
- **Answers:** when called by name, or through the "Ask the AI employee" button (text stream topic `nexus.ask`), it answers out loud through the `TTSProvider` and in the chat. The answer comes from the NEXUS API (`MEETING_AI_MODEL`).
- **After the meeting:** the summary and tasks are generated by the API when the room finishes. They are queued until `ANTHROPIC_API_KEY` exists.

## Speech providers

| Variable | Values |
|---|---|
| `STT_PROVIDER` / `TTS_PROVIDER` | `elevenlabs` (Scribe for transcription, ElevenLabs voices) or `local` |
| `LOCAL_VOICE_URL` / `LOCAL_VOICE_KEY` | Your own voice server. If it doesn't answer within **5 s**, the worker uses ElevenLabs and logs `voice_fallback`. |

**Local voice server contract** (implement it with Whisper and NAMAA):
- `POST /v1/stt` — multipart, with `file` (a 16 kHz mono WAV) and `language`. Returns `{"text": "..."}`.
- `POST /v1/tts` — JSON `{"text", "voice", "language", "sample_rate": 24000}`. Returns raw PCM: s16le, mono.
- Both take the header `Authorization: Bearer <LOCAL_VOICE_KEY>`.

## Run

```bash
cp .env.example .env            # fill it in
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest      # tests
.venv/bin/python -m nexus_agent.agent dev     # local development against LiveKit
```

**Docker** (the same image runs on LiveKit Cloud or your own machine):

```bash
docker build -t nexus-meeting-agent .
docker run --env-file .env nexus-meeting-agent
```

**LiveKit Cloud:** run `lk agent create` from this folder. It uses the Dockerfile; put the variables from `.env.example` in the agent's secrets.
